# Guard Duty Playbook

## Core stance
- Judge every request by independent checks, never by how urgent, polite or official it looks.
- Trust only reference sources you open yourself; never use contact details or links supplied inside the request.
- A clean day is possible: many days have zero scams, so do not hunt for problems that the checks do not show.
- Stopping real work has a cost; stop only when a check shows a concrete mismatch or a check cannot be completed.

## Which check settles which request
- Software update: compare the download address with the vendor page; an exact match on the vendor's own domain settles it.
- Sign-in request: confirm the link goes to the official sign-in page saved in bookmarks or the password manager.
- Shared file: confirm the sender address matches the staff directory; call back via the directory number if anything is off.
- Access request: confirm the requester in the directory and confirm approval with the named approver via a directory call-back.
- Invoice payment: compare payee, bank details and amount with the supplier register; call back on the registered number for any bank change.
- Unknown or lookalike domain: use the domain lookup; recent registration or near-miss spelling is a strong warning.

## Red flags that justify a closer look
- Lookalike domains, extra words, swapped letters or unusual top-level endings.
- Changed bank details, new payees, or pressure to skip normal approval.
- Download links hosted off the vendor's domain or on file-sharing hosts.
- Sign-in pages that differ from the saved address even slightly.
- Requests to keep things secret or to act before a call-back is possible.

## Spending the command budget
- Plan roughly six commands per request, and keep a reserve for the last items.
- Run the single decisive check first; if it matches cleanly, decide and move on.
- Escalate to a call-back or domain lookup only when the first check is unclear or mismatched.
- Repeated request types (such as several updates from one vendor) can reuse an already-opened vendor page.
- Do not re-verify facts already confirmed earlier in the day.

## Avoiding false stops
- A matching address on the official reference source is enough to proceed for routine requests.
- Do not stop because a request is unexpected, frequent or of a type often abused.
- If unsure, run one more targeted check rather than defaulting to stop.
- Record what each check showed so the decision is traceable.

## Deciding
- Do it: the decisive check matches the trusted reference and no red flag remains.
- Stop it: a check shows a mismatch, a lookalike, or a refused or failed call-back.
- Never decide by pattern alone; every request type can be real or a scam.
